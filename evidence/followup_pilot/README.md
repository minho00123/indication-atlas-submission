# 실제 임상시험 조건명 예비 시험 (2026-10-29)

300건 밖의 실제 데이터에서 두 가지를 확인한 예비 시험입니다. 현재 사전·판정·분석 엔진은 바꾸지 않았습니다. 정확도 평가가 아니며 임상 전문가 검토를 받지 않았습니다.

## 표본

- 출처: ClinicalTrials.gov API v2, 최초 게시일 2026-09-01~2026-09-30인 임상시험 4,214건의 NCT 번호 목록(`population_nct_ids.json`).
- 표본: `random.Random(20261029)`로 400건을 추출했습니다. 저장된 조건명 행이 있는 임상시험은 398건이며, 조건명은 중복 포함 932건·서로 다른 표현 830개입니다(`sample_400_studies.json`). 문맥은 적격 기준에서 `Exclusion Criteria` 앞부분을 최대 10,000자까지 사용했습니다. 언어·서식에 따라 포함 기준만 분리되지 않을 수 있습니다.
- 어려운 사례를 고르지 않은 무작위 표본입니다. 한 달·한 출처라는 한계가 있습니다.

## 시험 1. 현재 분석 엔진의 처리 현황

조건명과 포함 기준을 현재 분석 엔진(`app/analyzer.mjs`, 엔진 버전 prototype-4)에 그대로 넣었습니다(`engine_run_932.json`, `engine_run_summary.json`).

| 결과 | 건수 | 비율 |
|---|---:|---:|
| 기존 개념에 연결(자체 개념·별도 개체 포함) | 38 | 4.1% |
| 보류 | 48 | 5.2% |
| 미등록 | 846 | 90.8% |

확인한 점:

1. **연결과 보류의 구분:** 이 표본에서 개념에 연결된 항목은 38건이고, 48건은 보류됐습니다. 미등록이 아닌 86건을 전부 연결 성공으로 세지 않습니다. 표기와 문맥 규칙의 영향을 함께 받으므로 이 결과를 사전의 질환 수록 범위나 정확도로 해석하지 않습니다.
2. **"이름 (약어)" 표기:** 87건이 이 형식이었고, 그중 23건은 괄호를 뺀 긴 이름만 넣으면 기존 개념에 연결됐습니다(예: Non-small Cell Lung Cancer (NSCLC)). 조건명 전체를 입력할 때의 표기 처리와, 문서 안에 명시된 약어 정의를 읽는 기능은 구별합니다.
3. **보류 규칙:** 보류 48건 중 28건은 원문에서 대상 표현 미확인, 12건은 다른 개념과의 관계 미검토, 5건은 검토하지 않은 수식어, 2건은 범위 차이 검토 필요, 1건은 AND/OR 구성 개념 미확인이었습니다. 포함 기준 발췌에서 이름이 검출되지 않았다는 사실만으로 원래 임상시험에 질환 정보가 없다고 결론 내릴 수 없습니다. 조건명·연구 대상자·문맥의 역할을 구별하는 규칙이 필요합니다.
4. **질환이 아닌 조건명:** 미등록 표현 60개를 무작위로 골라 Claude가 분류한 결과 질환·상태 31, 시술 10, 대상 집단 2, 기타 17이었습니다(`unregistered_sample60_classification.json`, 단일 판정자 분류). 질환·상태 31개 중 MONDO 정확 일치 검색에 걸린 것은 6개입니다.

## 시험 2. 두 AI 실행의 판정 비교와 지침 보완점

표본 932건에서 무작위 30건(`random.Random(42)`)을 골라 후보 조회·정의 비교·관계·처리 상태와 이유를 작성하게 했습니다. 같은 Claude 모델의 두 하위 에이전트에 서로의 답과 엔진 결과를 보지 않도록 지시했습니다. 두 실행은 같은 지침(`judgment/BRIEF.md`)과 같은 기본 후보(`judgment/pack.json`)를 받았습니다. 다만 지침에 기존 G03·G05와 다른 수식어 처리 지시가 있어 기존 기준을 그대로 적용한 실험으로 볼 수 없습니다. 원래 지침과 결과는 보존했습니다.

| 측정 | 결과 |
|---|---|
| 처리 상태 일치 | 29/30 (97%), Cohen's kappa 0.94 |
| 개체 유형 일치 | 28/30 (93%), kappa 0.91 |
| 둘 다 개념 연결한 항목의 개념 일치 | 12/12 |
| 300건 사전과 겹친 질환 | 4건 모두 기존 판정과 같은 개념 |
| 인용 ID 존재 확인 | 서로 다른 169개 ID를 공개 API에서 확인([조회 기록](id_existence_check.json)). ID 존재와 의미·선택의 타당성은 별개 |
| 기준이 부족하다고 표시 | 판정자 A 20건, B 17건 |

불일치와 부족한 기준:

- V05 Bundle-Branch Block: 포함 기준은 서맥으로 심박조율이 필요한 환자입니다. 한 판정자는 연결, 다른 판정자는 입력 충돌 보류로 판정했습니다. 문맥이 얼마나 달라야 충돌로 보는지 기준이 없습니다.
- 시술·측정 지표·교육 같은 조건명이 30건 중 절반 가까이였습니다. G07은 증상·생리 상태·사건만 다루므로 두 판정자 모두 가장 가까운 '별도 개체'를 골랐습니다. '적응증 범위 밖' 상태가 필요합니다.
- 조건명이 참여자를 설명하지 않는 경우(의료진 대상 Asthma 연구, 보호자 대상 Critical Illness 연구)를 다루는 기준이 없습니다.
- 질환이 아닌 개체에 외부 코드를 붙일지 정한 규칙이 없어 5건에서 코드 선택이 달랐습니다.

## 이 결과의 한계

- 두 실행이 같은 모델(Claude)과 같은 후보 묶음을 사용하므로 비슷한 오류를 낼 수 있습니다. 사람이나 다른 모델과의 독립 평가가 아니며, 일치율·kappa는 이 두 실행 사이의 일치만 나타냅니다.
- 30건 중 16건은 두 실행 모두 '별도 개체'로 분류했습니다. 이런 처리 상태의 분포도 일치율에 영향을 줍니다.
- 판정 지침 4단계에 오류가 있었습니다. Prolonged 같은 수식어를 개념에서 빼라고 적었지만, G03·G05와 K101·K102는 기간 수식어를 개념 이름에 남깁니다. V26 Prolonged Diarrhea에 영향을 줍니다(`judgment/comparison.json`의 known_brief_error).
- 연결 결과의 정확도는 별도로 판정하지 않았습니다. ID가 존재하거나 두 실행의 선택이 같아도 올바른 판정이라는 뜻은 아닙니다.

## 재현 범위

저장된 모집단 순서와 난수 시드로 추출 대상 400개 NCT 번호를 다시 계산할 수 있습니다. 이 중 `NCT07813650`·`NCT07830316`은 조건명 행이 저장돼 있지 않아, 932행 파일에 등장하는 임상시험은 398개입니다. 전체 모집단의 원본 API 응답은 포함하지 않았으므로 전체 수집을 다시 실행하면 원천 갱신에 따라 달라질 수 있습니다.

빌드 후 저장된 932개 입력의 엔진 출력을 다시 생성하려면 아래를 실행합니다. 결과 파일은 저장소 밖에 만듭니다.

```bash
python3 tools/build.py
node evidence/followup_pilot/scripts/run.mjs "$PWD" evidence/followup_pilot/sample_400_studies.json /tmp/indication-pilot-rerun.json
```

모델의 원래 출력을 다시 생성하는 명령은 포함하지 않았습니다. `scripts/cands.py`와 `scripts/compare.py`는 당시 작업 폴더의 `judge/` 하위 구조를 사용하므로, 보존 폴더 `judgment/`를 그대로 인자로 주는 방식과는 다릅니다. JSON 두 실행의 집계와 선택 비교는 저장 자료로 다시 계산할 수 있습니다.

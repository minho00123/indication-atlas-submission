# 동의어 딕셔너리 구축 과정

## 1. 문제 정의: 같은 글자와 같은 질환은 다릅니다

같은 질환의 이름이 여러 표현으로 흩어지면 검색과 집계가 분산됩니다. 반대로 같은 약어나 비슷한 이름을 무조건 합치면 다른 질환의 근거가 섞입니다. 목표는 제공된 300개 입력을 검토해, 같은 뜻으로 연결할 표현과 구별할 표현을 근거와 함께 남기는 것입니다.

예를 들어 CD는 원문에 따라 Crohn disease 또는 Celiac disease입니다. 추가 문맥이 없는 K009는 둘 중 하나를 고르지 않았습니다. 반대로 T2DM과 type 2 diabetes mellitus는 검토 후 하나의 개념 그룹에 연결했습니다. 제공된 normalized_condition은 300행 모두 키워드와 같았으므로 정답으로 사용하지 않았습니다.

## 2. 비교 사례: 기존 지식은 후보와 근거로 사용합니다

MONDO는 여러 질환 용어체계의 명칭과 연결을 통합합니다. NCIt는 암을 포함한 생의학 개념의 정의와 용어를 제공하고, MeSH는 문헌 색인을 위한 Descriptor·Concept·Term을 구별합니다. 후보 이름이 비슷하다는 사실과 원문의 의미가 같다는 판단은 다릅니다.

기존 MONDO 후보를 고정 릴리스와 대조한 뒤, 300행 전체에 NCIt·MeSH 후보 조회를 추가했습니다. 일부 소견에는 HPO를 보조 사용했습니다. 정의·부위·조직형·원인·개체 유형·바이오마커 범위를 비교하고, 애매한 명칭과 진단 기준은 공식 기관·학회 자료로 보강했습니다. 같은 원천을 재사용하는 여러 서비스를 독립 투표자로 세지 않았습니다.

## 3. 유사 서비스 분석: 채택한 점과 보완한 점

| 서비스·체계 | 참고할 강점 | 이 과제에서 보완할 점 | 구현에 반영한 방식 |
|---|---|---|---|
| Open Targets | 질환 페이지에서 명칭·동의어·연관 정보를 탐색 | 제공된 각 원문의 판정 이유는 별도 기록 필요 | 검색에서 개념 상세와 원문별 근거로 연결 |
| NCIt / NCI EVS | 개념 코드·정의·동의어·출처를 제공 | 코드가 있어도 입력 범위와 동일한지 검토 필요 | 출처별 후보 정의와 범위 관계를 노출 |
| MeSH Browser | Descriptor·Concept·Term 구조를 구별 | 넓은 색인 범위를 입력의 동의어로 오인할 수 있음 | Concept 수준을 확인하고 상하위 관계는 분리 |
| MedGen | 여러 출처의 용어와 관련 정보를 탐색 | 공유 원천 간 일치를 독립 검증으로 볼 수 없음 | 근거를 원천까지 추적하고 다수결 병합을 피함 |
| Cortellis / Embase Emtree | 공개 설명에서 확인한 전문 검색·용어 정규화 방식 | 유료 내부 데이터와 실제 판정 정책은 확인하지 못함 | 공개 자료만 비교하고 내부 구현은 추정하지 않음 |

상세 조사와 공식 링크는 [유사 서비스 조사](#materials/research)에 정리했습니다. 이 과제에서는 동의어 목록만 보여주는 데 더해, 왜 연결했는지와 왜 연결하지 않았는지를 원문별로 확인할 수 있게 했습니다.

## 4. 가설과 해결 방안: 문맥과 명시적 규칙이 필요합니다

설계 가설은 다음과 같습니다. **키워드 문자열만으로는 동의어를 일관되게 판단하기 어렵습니다. 원문 문맥과 판단 규칙이 필요합니다.** 문맥을 주면 항상 정답이 된다는 가정은 하지 않습니다. 키워드와 원문이 충돌하면 입력 오류 가능성부터 기록합니다.

1. 원본 번호·키워드·문맥·정규화 열을 보존합니다.
2. MONDO·NCIt·MeSH 등에서 비교할 후보를 찾습니다. 이름 검색은 후보 수집 단계입니다.
3. 후보의 정의와 원문의 의미 범위를 비교합니다. 같은 개념, 상하위 범위, 관련 개념, 동등성 미확정, 다른 개체를 구별합니다.
4. 같은 개념으로 판단한 입력만 개념 그룹에 연결합니다. 검토한 이름과 별칭만 검색 목록에 넣습니다.
5. 질환명 구성 요소와 원문의 추가 조건을 분리합니다. 같은 NSCLC 그룹이어도 전이·재발·치료 조건은 다른 행이나 새 검색어에 전파하지 않습니다.
6. 문맥 부족·입력 충돌은 보류하고, OR 표현은 논리식을 보존합니다. 모든 입력을 억지로 단일 코드에 넣지 않습니다.
7. 판정·출처·적용 조건을 기록한 뒤 그룹·별칭·비교 사례의 일관성을 검사합니다.

실제 판단 규칙과 예외는 [가이드라인 G01–G12](#materials/guidelines), CD·eczema·NSCLC·NAFLD/MASLD 등은 [판단 사례](#cases)에서 확인할 수 있습니다.

## 5. 실험과 현재 데이터 검증

### 원문 문맥을 추가했을 때의 변화

초기 탐색 실험에서 작업자가 만든 30개 사례를 같은 기록상 모델(claude-sonnet-5-5)에 조건별로 세 번 입력했습니다. A는 키워드만, B는 키워드와 원문을 제공했습니다. **당시 정답·채점 규칙 기준**으로 A는 매회 12/30(40%), B는 매회 22/30(약 73%)였습니다. 이 전체 수치는 현재 딕셔너리의 정확도가 아니며, 정책과 무관한 성능으로 해석하지 않습니다.

문맥의 역할을 설명하기 위해 결과를 본 뒤 고른 약어 7건은 다음과 같습니다. 키워드만 준 A 조건에서 모델은 7건 모두 매번 **판단 보류(ambiguous)**로 답했습니다. 원문을 함께 준 B 조건에서는 각 건을 세 번 모두 해당 질환으로 연결했습니다. A의 0/3은 보류 응답이 당시 채점 기준의 질환명 정답과 불일치했다는 뜻이며, 잘못된 질환을 선택했다는 뜻은 아닙니다. B는 각 건이 3/3으로 당시 허용 답과 일치했습니다.

| 사례 | 약어 | 원문에 추가한 단서 | 당시 허용 답의 예 |
|---|---|---|---|
| H01 | MS | 시신경염·뇌 탈수초 병변 | Multiple sclerosis |
| H02 | MS | 심초음파의 승모판 면적 감소 | Mitral stenosis |
| H03 | PE | CT 폐혈관조영으로 확인 | Pulmonary embolism |
| H04 | PE | 임신 20주 이후 고혈압·단백뇨 | Preeclampsia |
| H05 | DM | heliotrope rash·근위부 근력 저하 | Dermatomyositis |
| H07 | AS | 양측 천장관절염·염증성 요통 | Ankylosing spondylitis |
| H08 | AS | 대동맥판 면적 1.0 cm² 미만 | Aortic stenosis |

이는 문맥이 없을 때 보류했던 약어를 원문 단서로 해소한 관찰이며, 문맥이 약어 해석에 도움을 줄 수 있음을 보여줍니다. **사후 선택한 설명용 부분집합**이며, 7건을 세 번 반복한 21개 관측을 독립된 21문항으로 세지 않습니다. 문맥이 없는 DM(H06)은 이 표에 포함하지 않았습니다. 모델 하나, 작업자 작성 사례·정답, 일부 개발 개념 중복(H28)이라는 한계가 있어 독립 평가나 인과 효과의 입증으로 보지 않습니다.

전체 A/B/C/D 결과와 현재 정책의 차이는 이 문서 아래의 **초기 탐색 실험(구 정책 기준)**에 따로 보존했습니다. 입력 30건·프롬프트·12회 예측·당시 채점 결과를 제출 소스에 포함했으며 `python3 tools/score_legacy.py`로 모델 호출 없이 재채점할 수 있습니다.

### 현재 딕셔너리의 결과

| 구분 | 결과 | 의미 |
|---|---:|---|
| 제공 입력 | 300행 | 모든 원문을 보존 |
| 개념 연결 | 276행 | 연구 판단으로 선택한 외부 개념 |
| 자체 개념 | 17행 | 원문 범위는 정의했으나 동일 범위 외부 연결이 남음 |
| 별도 개체 | 4행 | 생리 상태·생애 단계·증상·사건을 구별 |
| OR 조건 | 1행 | K018의 복합 논리식 |
| 보류 | 2행 | K009 문맥 부족, K024 입력 충돌 |
| 개념 그룹 | 287개 | 질환군·소견·상태 등을 포함 |
| 별칭 연결 | 419건 | 원문별 연결 포함, 고유 검색 문자열은 404개 |

대표 외부 표준 ID가 있는 입력은 별도 개체 일부를 포함한 279행입니다. MONDO 250행, NCIt 18행, MeSH Concept 10행, HPO 1행을 대표로 선택했습니다. LOCAL 키를 사용하는 입력은 사건을 포함해 18행입니다. 이 수치들은 임상 정확도가 아닙니다.

### 현재 데이터에서 검증한 것

87쌍 비교에서 같은 개념·구별할 개념·문맥 조건의 일관성을 확인했습니다. 이 사례들은 규칙을 만들며 사용했으므로 독립 정답셋이 아닙니다. 교차 검토에서는 NAFLD 별칭 누락과 질환명 토큰·추가 조건 혼동 등을 발견하고 수정했습니다. K009·K024는 불확실성을 숨기지 않고 보류로 남겼습니다.

- XLSX 원문과 제출 데이터 300행의 일치, 원본 번호의 유일성.
- 개념 그룹·별칭·대표 ID·범위 관계의 일관성.
- CD·AML의 다의 후보, 보류와 OR 식의 비병합, HER2 양성/음성 구별.
- 이름 구성 요소와 추가 조건의 원문 구간, 기간·전이·재발·치료 정보의 보존.
- 공식 API 응답의 해시, 출처 연결, 브라우저 검색·필터·다운로드·문서 접근.

### 새 원문에 규칙을 적용하는 시제품

[새 문장 분석](#analyze)은 저장된 300행의 판정을 돌려주는 대신 입력한 새 원문을 브라우저에서 계산합니다. 문서 내 긴 이름(약어), 검토한 별칭, 직접적인 부정·추정 표지와 일부 조건 구간을 처리합니다. CD의 정의를 Crohn disease에서 Celiac disease로 바꾸면 연결도 바뀌며, 정의가 없거나 충돌하면 보류합니다. 작성자가 만든 개발·반례 입력으로 동작을 검사하며 독립 정확도 수치로 제시하지 않습니다. [실행 원리와 지원 한계](#materials/analyzer)를 함께 제공합니다.

### 근거 자료와 재현 범위

MONDO는 2026-10-06 릴리스를 고정했고 NCIt 응답은 26.09d를 명시합니다. MeSH·HPO API가 릴리스 버전을 노출하지 않은 경우 조회 시각·원본 응답·해시로 구별했습니다.

제출 자료에는 사용한 MONDO 항목의 발췌와 공식 API 응답 676개, 원문 인용 기록, 각 파일의 해시를 포함했습니다. MONDO 발췌는 전체 온톨로지가 아니며 계층·xref를 자동 병합 규칙으로 쓰지 않습니다. 짧은 인용만 보존한 웹 자료는 전체 페이지를 저장했다고 표시하지 않습니다.

`data/records.json`은 근거를 대조해 작성한 판정을 고정한 스냅샷입니다. 빌드는 판정을 다시 의학적으로 추론하지 않고 무결성을 확인해 검색·화면·다운로드를 재생성합니다. 유료 모델·API 키·네트워크 없이 실행할 수 있습니다.

## 6. 반례: 발견한 문제와 적용 조건

| 발견한 문제 | 확인·수정 | 현재 적용 조건 |
|---|---|---|
| K116에 NAFLD 약어가 빠져 검색이 되지 않음 | 근거가 있는 약어를 추가하고 K117 MASLD와 관련 링크 제공 | 명칭 변경을 안내하되 정의 기준이 다른 두 범위를 자동 병합하지 않음 |
| MONDO의 CLL→ALL 등 의심 계층 | 고정 릴리스의 엣지를 확인하고 NCI/SEER 임상 설명과 분리해 판단 | K164 CLL 표현을 보존하며 계층만으로 동의어 병합·하위 포함 검색을 확장하지 않음. 외부 온톨로지 자체를 수정했다는 뜻은 아님 |
| K262 NTM의 MeSH 후보 정의가 CDC 설명과 충돌 | 누락 후보를 보완하고 M. leprae 포함·제외 차이를 경고로 기록 | 후보는 UNKNOWN, 원문 범위는 LOCAL로 유지. 폐 위치도 임의로 추가하지 않음 |
| 질환명에 포함된 수식어를 환자의 추가 조건처럼 추출 | 질환명 구성 요소와 원문 추가 조건의 역할을 분리 | 같은 개념의 다른 행이나 새 검색어에 환자 조건을 전파하지 않음 |

출처가 있다는 사실만으로 같은 뜻이라고 확정할 수는 없습니다. 정의 충돌은 경고와 관계 상태로 남기고, 근거가 부족하면 보류하거나 자체 개념으로 범위를 보존합니다.

### 기본 의미의 적용 범위

K238의 판막성 대동맥 협착과 K249의 폐기종은 공식 용례를 근거로 선택한 기본 의미입니다. 판막 위·아래 또는 피하 등 반대 문맥이 명시되면 재검토하도록 scope_assumptions에 기록했습니다. 새 문장에 이를 자동 적용하는 분류기를 검증했다는 뜻은 아닙니다.

원천 MONDO의 선택 구문, 현재 판정에서 확인한 문제, 외부 자료의 탐색 결과는 [분류 기준과 적용 한계](#materials/boundaries)에 구별해 정리했습니다. 외부 기준선과 잠정 임상시험 라벨은 현재 사전의 정확도 지표가 아닙니다.

## 7. 후속 연구와 한계

현재 결과는 연구용 판정이며 임상 전문가 승인은 0건입니다. 독립 주석자가 만든 정답셋으로 정확도를 평가하지 않았습니다. 276행의 문맥은 추가 아형 정보가 없는 템플릿입니다. 일부 용어에는 기본 의미와 예외를 선언한 정책이 적용됩니다. LOCAL은 외부 코드가 세상에 없다는 주장이 아니며, 동의어 목록의 완전성도 보장하지 않습니다.

우선 후속 과제는 보존한 질환 개념과 원문별 조건을 분리해 비교하는 표현을 설계하고 검증하는 것입니다. K010·K011의 구간 보존을 출발점으로 사용하되 질환명 구성 요소를 환자 추가 조건으로 옮기지 않습니다. 평가에는 전문가의 독립 주석, 정책을 먼저 고정한 신규 자료와 개념·환자 조건의 별도 지표가 필요합니다. 구체적인 문제·기존 근거·첫 단계·검증 방법은 [후속 연구](#materials/boundaries)에 정리했습니다. 판정 변경 이력과 다중 사용자 검수를 추가하면 유지·보수에도 활용할 수 있습니다. 명시적 문서 정의를 이용하는 약어 해소와 일부 조건 구간 추출은 시제품으로 구현했습니다. 증상 기반의 일반적인 약어 추론, 환자별 진단·치료 적격성 판정, 완성된 임상 속성 추출기, 한국어 KCD 매핑은 현재 구현 범위 밖입니다.

### AI 활용

AI를 후보 탐색·판정 초안·문서화·코드 작성·교차 검토에 사용했습니다. 두 AI의 일치를 정답으로 채택하지 않고 원문과 공식 근거를 대조했습니다. 모델 간 검토는 블라인드 또는 임상 전문가 검증이 아닙니다. 판정과 근거를 웹과 파일에서 검토할 수 있게 공개했습니다.

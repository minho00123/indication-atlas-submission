# 질환 동의어 사전 구축 과정

> - **문제와 가설:** 같은 이름도 다른 질환일 수 있습니다. 키워드에 제공 문맥과 판단 규칙을 함께 적용했습니다.
> - **이 사전의 방향:** 개념별 이름 목록과 제공 항목별 판단 이유·출처를 함께 확인할 수 있게 했습니다.
> - **확인한 범위:** 원문 보존, 개념·별칭 연결, 87쌍 비교와 실행 규칙의 일관성을 검사했습니다. 독립 임상 정확도를 평가한 결과는 아닙니다.
> - **구축 결과:** 보류 2건과 OR 표현 1건을 제외한 297개 항목을 287개 개념 그룹에 연결했습니다. 별칭 연결 419건, 자체 관리 개념 17개 항목입니다.
> - **반례와 후속 연구:** NAFLD 별칭 누락과 조건 추출 오류를 수정했습니다. 6·7단계에 반례, 수정 내용과 남은 연구를 정리했습니다.

## 1. 문제 정의: 글자가 같다고 같은 질환은 아닙니다

같은 질환의 이름이 여러 표현으로 흩어지면 검색과 집계가 분산됩니다. 반대로 같은 약어나 비슷한 이름을 무조건 합치면 다른 질환의 근거가 섞입니다. 목표는 제공된 300개 입력을 검토해, 같은 뜻으로 연결할 표현과 구별할 표현을 근거와 함께 남기는 것입니다.

예를 들어 CD는 원문에 따라 Crohn disease 또는 Celiac disease입니다. 추가 문맥이 없는 K009는 둘 중 하나를 고르지 않았습니다. 반대로 T2DM과 type 2 diabetes mellitus는 검토 후 하나의 개념 그룹에 연결했습니다. 제공된 normalized_condition은 300행 모두 키워드와 같았으므로 정답으로 사용하지 않았습니다.

## 2. 비교 사례: 기존 지식은 후보와 근거로 사용합니다

MONDO는 여러 질환 용어체계의 명칭과 연결을 통합합니다. NCIt는 암을 포함한 생의학 개념의 정의와 용어를 제공하고, MeSH는 문헌 분류용 주제어 체계로 Descriptor·Concept·Term을 구별합니다. 후보 이름이 비슷하다는 사실과 원문의 의미가 같다는 판단은 다릅니다.

기존 MONDO 후보를 고정 릴리스와 대조한 뒤, 300행 전체에 NCIt·MeSH 후보 조회를 추가했습니다. 일부 소견에는 HPO를 보조 사용했습니다. 정의·부위·조직형·원인·개체 유형·바이오마커 범위를 비교하고, 애매한 명칭과 진단 기준은 공식 기관·학회 자료로 보강했습니다. 같은 원천을 재사용하는 여러 서비스를 독립 투표자로 세지 않았습니다.

후보를 찾을 때는 키워드를 대표 이름·동의어와 대조했습니다. NCIt는 공식 검색 API, MeSH는 용어 검색 후 해당 용어가 속한 Concept 조회를 사용했습니다. 약어만으로 찾기 어렵거나 결과가 부족하면 원문의 긴 이름·다른 표기로 추가 조회했습니다. 검색 결과는 검토 대상으로 모았으며, 정의와 원문 범위를 비교한 뒤 채택 여부를 정했습니다. 실제 검색어·조회 URL·응답은 ZIP의 `evidence/api-manifest.json`과 공식 응답 묶음에 보존했습니다.

## 3. 유사 서비스 분석: 채택한 점과 보완한 점

상용 서비스 SciBite·Cortellis·Embase의 공개 문서를 비교하고, Open Targets·MedGen과 공개 용어 조회 도구를 참고했습니다. MONDO·NCIt·MeSH·HPO는 비교 대상이 아니라 구축 근거로 사용했습니다. 장점과 한계는 공식 문서에 적힌 기능을 기준으로 정리했으며, 같은 입력으로 성능을 비교하지는 않았습니다.

| 서비스 | 장점 | 이번 과제 관점의 한계 | 이 사전의 선택 |
|---|---|---|---|
| SciBite (CENtree·TERMite) | 동의어·관계 관리, 검토·승인·변경 이력, 대규모 문서 인식 | 공개 문서만으로는 개별 연결의 범위 판단 근거가 사용자에게 어떻게 보이는지 확인할 수 없음 | 300개 항목마다 연결·분리·보류 이유와 출처를 공개 |
| Cortellis Ontologies API | 동의어·계층 조회, 용어체계 간 ID 연결, 원문 위치 반환 | ID가 연결돼 있어도 입력과 같은 범위인지는 별도 판단이 필요 | 코드 연결과 범위 관계(같음·넓음·좁음)를 나눠 기록 |
| Embase / Emtree | 선호어 연결과 하위 개념 확장으로 검색 누락을 줄임 | 확장된 용어가 모두 같은 질환은 아니어서, 동의어 사전에 그대로 쓰면 상하위가 섞임 | 상하위·관련 개념을 동의어 목록과 분리 |
| Open Targets · MedGen (공개 플랫폼) | 여러 용어체계와 연구 정보를 한곳에 연결 | 릴리스마다 ID가 바뀌거나 합쳐지고, 같은 원천을 재사용한 일치가 여러 근거처럼 보일 수 있음 | 출처 버전을 고정하고, 같은 원천의 일치를 독립 근거로 세지 않음 |

이번 과제에는 다음 원칙을 적용했습니다.

1. **제공 항목별 판단 근거:** 왜 묶었는지와 왜 묶지 않았는지를 300개 항목마다 기록했습니다.
2. **이름 일치와 같은 개념의 구별:** 같은 검색 결과·같은 주제어 항목이라도 정의 범위를 비교한 뒤 연결했습니다.
3. **공유 원천의 중복 계산 방지:** 같은 원천을 재사용한 서비스들의 일치를 독립된 여러 근거로 세지 않았습니다.

서비스별 관리 방식과 공식 근거는 [유사 서비스 조사](#materials/research)에 정리했습니다.

## 4. 가설과 해결 방안: 문맥과 명시적 규칙이 필요합니다

설계 가설은 다음과 같습니다. **키워드 문자열만으로는 동의어를 일관되게 판단하기 어렵습니다. 원문 문맥과 판단 규칙이 필요합니다.** 각 항목은 원문 문맥과 MONDO·NCIt·MeSH 후보의 정의를 비교한 뒤 아래 기준으로 처리했습니다. 관계 방향은 항상 원문 → 후보입니다.

| 확인 결과 | 처리 | 예 |
|---|---|---|
| 이름이 달라도 같은 개념·범위 | 같은 개념 키에 연결 | NSCLC / Non-small cell lung cancer |
| 같은 표기지만 문맥상 다른 뜻 | 다른 개념으로 구분 | CD의 크론병(K007) / 셀리악병(K008) |
| 상하위·관련 관계 | 같은 동의어 그룹으로 합치지 않음 | 일반 NTM(비결핵 항산균) 감염 / 폐 NTM 감염, NAFLD(비알코올 지방간 질환) / MASLD(대사이상 관련 지방간 질환) |
| 의미 범위는 정했지만 외부 후보가 같은 범위가 아님 | 범위를 정의한 자체 관리 개념(LOCAL) | K014 HER2 양성 유방암 |
| 의미를 정할 문맥이 없거나 입력이 충돌 | 보류 | K009 CD, K024 eczema와 원문 충돌 |
| 원문이 A 또는 B | 두 개념의 OR 논리식 보존 | K018 MDS(골수형성이상증후군) 또는 AML(급성 골수성 백혈병) |
| 같은 질환이지만 추가 조건이 다름 | 개념은 묶고 조건은 원래 항목에 보존 | K010 / K131 NSCLC |

이 표는 [가이드라인 G01–G12](#cases)의 요약입니다. 여기서 개념 키는 하나의 개념 그룹을 가리키는 ID(예: MONDO:0005233)입니다. 원문과 제공된 정규화 열은 그대로 보존했고, 검토한 이름과 별칭만 검색 목록에 넣었습니다. 대표 사례는 [판단 사례](#cases/examples)에서 확인할 수 있습니다.

새 항목을 추가할 때도 원문과 후보 정의를 비교하고, 같은 범위인지 검토해야 합니다. 현재 분석 엔진은 등록된 이름·별칭과 제한된 문장 규칙을 재사용하며, 새로운 질환의 후보 정의를 읽고 판정하는 단계는 자동화하지 않았습니다. 실제 임상시험 조건명에 적용해 본 결과는 [7. 후속 연구](#materials/methodology?section=future)에 있습니다.

초기 실험에서는 AI에 아래 지시를 주고, 같은 30문항에 키워드만 준 조건(A)과 원문 문맥을 함께 준 조건(B)을 비교했습니다. 두 조건의 지시문은 같고 입력만 다릅니다. 결과는 5단계의 '초기 AI 실험'에 있으며, 네 조건의 지시문 원문은 [prompts.json](https://github.com/minho00123/indication-atlas-submission/blob/main/data/experiments/legacy/prompts.json)에 보존했습니다.

```text
You normalize disease/indication keywords extracted from clinical-trial eligibility text for a pharmaceutical intelligence database.
...
- "decision": one of
    "mapped"       – the row refers to one disease; give its standard name
    ...
    "ambiguous"    – the disease cannot be determined; give no conditions
```

## 5. 구축 결과와 검증

### 현재 딕셔너리의 결과

| 구분 | 결과 | 의미 |
|---|---:|---|
| 제공 입력 | 300행 | 모든 원문을 보존 |
| 개념 연결 | 276행 | 연구 판단으로 선택한 외부 개념 |
| 자체 관리 개념 | 17행 | 뜻과 범위는 정했으나 같은 범위의 외부 코드를 확인하지 못함 |
| 별도 개체 | 4행 | 생리 상태·생애 단계·증상·사건을 구별 |
| OR 조건 | 1행 | K018의 복합 논리식 |
| 보류 | 2행 | K009 문맥 부족, K024 입력 충돌 |
| 개념 그룹 | 287개 | 질환군·소견·상태 등을 포함 |
| 별칭 연결 | 419건 | 출처 항목별로 셉니다. 표기를 정규화한 서로 다른 검색 표현은 404개 |

보류 2건과 OR 표현 1건을 제외한 297개 항목을 287개 개념 그룹에 연결했습니다. 여러 입력이 모인 그룹은 6개입니다.

제공 문맥 300행 중 276행(92%)은 "No further subtype or diagnostic details are provided"처럼 키워드만 반복하는 정형 문장입니다. 위 표의 개념 연결 276행과는 다른 집계이며, 숫자가 같은 것은 우연입니다. 문맥이 판단에 실제로 쓰일 수 있었던 것은 나머지 24행(CD·AML 등)입니다. 대표 외부 표준 ID가 있는 입력은 279행(MONDO 250, NCIt 18, MeSH Concept 10, HPO 1)이며, LOCAL 키를 쓰는 입력은 사건을 포함해 18행입니다.

### 검증한 것

- 제공 XLSX와 제출 데이터 300행의 일치, 원본 번호의 유일성.
- 개념 그룹·별칭·대표 ID·범위 관계의 일관성과 87쌍 비교(같은 개념·구별할 개념·문맥 조건).
- 여러 뜻을 가진 CD·AML의 후보 구별, 보류와 OR 표현을 하나의 개념으로 합치지 않음, HER2 양성/음성 구별, 이름 구성 요소와 추가 조건의 원문 구간 보존.
- 300행을 현재 사전으로 다시 실행해 저장한 판정과 비교했습니다. 290행은 같은 개념 키에 연결됐고, 2행은 같은 보류 판단, 4행은 규칙 미지원, 4행은 검토 필요였습니다. 이는 개념 키의 일치이며, 추가 조건·원문의 언급 방식·세부 사유의 일치는 판단 규칙 검사에서 따로 확인합니다. 구축에 사용한 자료를 다시 실행한 결과이므로 새로운 자료에 대한 정확도는 아닙니다. 세부 결과는 [검증과 한계](#materials/audit)에 있습니다.
- 공식 API 응답의 해시, 출처 연결, 웹의 검색·필터·다운로드.


### 초기 AI 실험: 문맥 유무 비교

구축 초기에 작업자가 만든 30문항으로 AI에 키워드만 줄 때와 원문 문맥을 함께 줄 때를 비교했습니다. 사후에 고른 약어 7건은 키워드만 준 조건에서 세 회차 모두 보류됐고, 문맥을 준 조건에서는 세 회차 모두 당시 허용 답과 일치했습니다. 4단계 가설과 같은 방향의 관찰이며 현재 사전의 정확도가 아닙니다. 조건·점수·한계는 이 페이지 맨 아래 '초기 탐색 실험(구 정책 기준)'에 있습니다(저장소에서는 [LEGACY_EXPERIMENT.md](https://github.com/minho00123/indication-atlas-submission/blob/main/docs/LEGACY_EXPERIMENT.md)).

### 근거 자료와 재현 범위

MONDO는 2026-10-06 릴리스를 고정했고 NCIt 응답은 26.09d를 명시합니다. MeSH·HPO API가 릴리스 버전을 노출하지 않은 경우 조회 시각·원본 응답·해시로 구별했습니다. 제출 자료에는 사용한 MONDO 항목의 발췌, 공식 API 응답 676개, 원문 인용 기록과 각 파일의 해시가 있습니다.

`data/records.json`은 근거를 대조해 작성한 판정을 고정한 스냅샷입니다. 빌드는 새 의학 판정을 만들지 않고, 원본이 바뀌거나 빠지지 않았는지 확인한 뒤 화면과 다운로드를 생성합니다. 빌드와 저장 자료 검사는 모델·API 키·네트워크 없이 실행할 수 있습니다.

## 6. 반례: 발견한 문제와 적용 조건

| 발견한 문제 | 확인·수정 | 현재 적용 조건 |
|---|---|---|
| K116에 NAFLD 약어가 빠져 검색되지 않음 | 근거가 있는 약어를 추가하고 K117 MASLD로 관련 링크를 제공 | 명칭 변경을 안내하되 정의 기준이 다른 두 범위를 자동 병합하지 않음. [사례](#cases/masld) |
| MONDO의 CLL(만성 림프구성 백혈병)→ALL(급성 림프모구성 백혈병) 등 의심 계층 | 고정 릴리스의 계층을 확인하고 NCI/SEER 임상 설명과 분리해 판단 | K164(Chronic lymphocytic leukemia)의 판정을 유지하고, 계층만으로 동의어 병합·하위 포함 검색을 확장하지 않음. 외부 온톨로지를 수정했다는 뜻은 아님 |
| K262 NTM(비결핵 항산균) 감염의 MeSH 후보 정의가 CDC 설명과 충돌 | 누락 후보를 보완하고 M. leprae 포함·제외 차이를 경고로 기록 | 후보 관계는 UNKNOWN(관계 미확정), 입력은 범위를 정의한 LOCAL로 관리. 폐 위치를 임의로 추가하지 않음. [K262](#records?record=K262) |
| 질환명에 포함된 수식어를 환자의 추가 조건처럼 추출 | 질환명 구성 요소와 원문 추가 조건의 역할을 분리 | 같은 개념의 다른 행이나 새 검색어에 환자 조건을 전파하지 않음. [K011](#records?record=K011) |
| 같은 개념 연결을 환자 조건 전체의 일치로 오해할 위험 | NSCLC의 전이·이전 치료를 K010에만 보존 | 같은 개념이라도 입력별 조건을 따로 읽음. [사례](#cases/nsclc) |

출처가 있다는 사실만으로 같은 뜻이라고 확정하지 않습니다. 입력의 의미를 확정할 문맥이 부족하거나 키워드와 원문이 충돌하면 보류합니다(K009·K024). 입력의 의미 범위는 정했지만 검토한 외부 후보와 같은 범위로 연결하기 어려우면 LOCAL로 관리합니다(K014). 후보와의 관계(UNKNOWN 등), 관리할 개념 키(LOCAL), 입력의 처리 상태(보류)는 서로 다른 축입니다.

### 원천 용어체계에서 재검토할 관계: CLL→ALL

고정한 MONDO v2026-10-06에서 B-cell chronic lymphocytic leukemia(MONDO:0004948)는 chronic leukemia, neoplasm of mature B-cells, indolent B-cell non-Hodgkin lymphoma와 함께 acute lymphoblastic leukemia(MONDO:0004967)의 하위로도 기록돼 있습니다. 같은 릴리스의 ALL 정의는 급성 발병과 lymphoblasts를 설명합니다. 이 계층을 그대로 따라 하위를 확장하면 ALL 아래에서 CLL 항목에 도달하므로, 현재 사전은 계층만으로 동의어를 병합하거나 하위 포함 검색을 자동 확장하지 않습니다([K164](#records?record=K164), [G09](#cases)). 관계의 존재는 원본에서 확인한 사실이며 의학적 오류로 확정한 것은 아닙니다. 근거는 [MONDO 고정 릴리스](https://github.com/monarch-initiative/mondo/releases/tag/v2026-10-06)와 원본 구문·전체 OBO 해시를 담은 [발췌 파일](../evidence/boundary_checks/mondo_hierarchy_excerpt.json)입니다.

### 기본 의미를 적용할 수 있는 범위

| 입력 | 현재 선언한 기본 의미 | 재검토가 필요한 원문 |
|---|---|---|
| K238 Aortic stenosis | 공식 용례에 따른 판막성 대동맥 협착 | supravalvular·subvalvular 등 판막 위·아래 위치를 명시 |
| K249 Emphysema | 공식 용례에 따른 폐기종 | subcutaneous 등 피하·비폐성 위치를 명시 |

선택한 기본 의미와 맞지 않는 원문 정보가 있으면 기본 연결을 적용하지 않고 다시 검토합니다. [기본 의미 사례](#cases/sense)에서 원문과 후보를 확인할 수 있습니다.

## 7. 후속 연구와 한계

현재 결과는 연구용 판정이며 임상 전문가 승인은 0건입니다. 제공 문맥 300행 중 276행은 추가 정보가 없는 정형 문장이어서, 문맥에 따른 판단은 24행에서만 시험됐습니다. LOCAL은 검토한 외부 후보와 같은 범위로 연결하지 못한 개념입니다. 동의어 목록의 범위는 이번에 검토한 표현으로 한정됩니다. 검증의 범위와 한계는 [검증과 한계](#materials/audit)에 모았습니다.

| 순서 | 후속 과제 | 첫 단계 | 확인 방법 |
|---|---|---|---|
| 1 | 애매한 사례와 기본 의미 정책의 독립 재검토 | 정책을 먼저 고정하고, 평가자 2명이 구축에 쓰지 않은 자료에 서로의 답을 보지 않고 정답 표시 | 개념 연결과 환자 조건 비교를 따로 평가하고 단위·분모·미채점을 공개 |
| 2 | 사전 유지 절차 | 새 별칭·LOCAL·보류의 재검토 목록과 근거·판정 변경 이력·출처 버전 관리 | 원천 관계(예: CLL→ALL)가 바뀌면 검토 대상을 알리고, 검토된 관계만 사용하는지 검사 |
| 3 | 문서 안 약어의 뜻 확인과 원문 조건 처리 확장 | 현재 분석 엔진의 처리 범위(명시적 약어 정의, 일부 조건 구간)를 구축에 쓰지 않은 문서로 확장 | 불일치·보류·처리 범위를 함께 평가 |
| 4 | 선택적 확장 | 한국어 표준명·KCD(한국표준질병사인분류) 연결, 검토된 계층 확장, 환자 적격성 비교 | 각 기능의 별도 질의셋으로 평가 |

### 실제 임상시험 조건명 예비 시험

300건 밖의 자료에 적용할 때 보완할 점을 찾기 위해 예비 시험을 했습니다. ClinicalTrials.gov의 최초 게시일이 2026년 9월인 임상시험 4,214건에서 무작위로 400건을 뽑았습니다. 조건명이 있는 398건에서 얻은 조건명 932건을 사용했으며, 중복을 제외한 표현은 830개입니다. 현재 사전·판정·엔진은 바꾸지 않았습니다.

**① 현재 엔진의 처리 현황:** 이 표본에서 기존 개념에 연결 38건, 보류 48건, 미등록 846건이었습니다. 이 수치는 조건명 표기와 문맥 처리 규칙의 영향을 함께 받으므로, 사전의 질환 수록 범위나 정확도로 해석하지 않습니다. 확인한 보완점은 다음과 같습니다.

- 조건명 자체가 '이름 (약어)' 형식일 때 전체 표현을 등록된 이름과 연결하지 못했습니다. 예를 들어 "Non-small Cell Lung Cancer (NSCLC)"는 미등록이지만, 괄호를 뺀 긴 이름은 기존 개념에 연결됐습니다.
- 이름이 사전에 있어도 포함 기준 발췌에서 대상 표현을 찾지 못하거나 다른 질환이 함께 등장하면 보류될 수 있었습니다. 조건명 칸과 문맥의 역할을 구별하는 규칙이 필요합니다.
- 미등록 표현 60개를 한 차례 AI로 분류했을 때, 29개는 시술·대상 집단·기타로 분류됐습니다. 질환이 아닌 조건명의 처리 기준도 필요합니다.

**② 판단 지침의 보완점:** 표본 중 30건에 대해 같은 Claude 모델의 두 에이전트가 서로의 답과 엔진 결과를 보지 않도록 지시받고 후보·정의를 검토했습니다. 처리 상태는 29건에서 일치했지만, 두 실행은 기준이 부족한 항목을 각각 20건·17건으로 표시했습니다. 시술·측정 지표처럼 질환이 아닌 조건명, 조건명과 실제 참여자가 다른 연구(의료진 대상 Asthma 연구 등), 문맥이 얼마나 달라야 입력 충돌로 보는지를 더 구체적으로 정해야 합니다.

두 실행의 일치는 독립 평가나 판정의 정확도를 뜻하지 않습니다. 또한 배포한 지침에는 수식어를 개념에서 분리하라는 오류가 있어 기존 G03·G05와 달랐습니다(30건 중 V26 Prolonged Diarrhea 항목에 영향). 따라서 기존 가이드라인의 일관성이 입증됐다고 볼 수 없습니다. 원래 지침과 결과를 보존했고, 지침을 바로잡은 재검토가 필요합니다.

후속 과제는 지침 오류 수정, '적응증 범위 밖' 처리와 조건명·참여자 관계의 명시, 조건명 안의 약어 표기 처리입니다. 조건명만으로 질환을 확인할 때와 참여자의 실제 질환을 판단할 때도 구분해야 합니다. 이를 반영한 뒤 사람 검토자가 별도로 정답을 표시한 자료로 평가할 계획입니다. 표본·스크립트·두 AI 검토 결과는 [예비 시험 자료](https://github.com/minho00123/indication-atlas-submission/tree/main/evidence/followup_pilot)에 있습니다.

### 외부 자료로 살펴본 경계

현재 사전을 평가한 자료는 아니지만, 경계 문제를 찾기 위해 질환명 표시 문서 모음(NCBI Disease Corpus)에 MONDO 이름 일치를 적용한 기준선과 ClinicalTrials.gov의 선별 항목을 탐색했습니다. 약어의 여러 뜻, 질환을 얼마나 구체적으로 구분했는지의 차이, 조건명보다 좁은 적격 기준이 반복해서 관찰돼 후속 과제 3의 근거로 썼습니다. 불일치 원인 재분류와 임상시험 비교 라벨은 독립 전문가 검증을 받지 않은 잠정 판단입니다. 수치와 한계는 [외부 코퍼스 기준선](https://github.com/minho00123/indication-atlas-submission/blob/main/docs/EXTERNAL_BASELINES.md)과 [임상시험 문구 비교](https://github.com/minho00123/indication-atlas-submission/blob/main/docs/EXTERNAL_TRIALS.md)에 있습니다.

### AI 활용

AI(Claude, Codex)를 후보 탐색, 판정 초안, 코드 작성, 문서화에 사용했고, 한 AI의 결과를 다른 AI가 검토하게 했습니다. 검토 의견은 그대로 받아들이지 않고 원문·공식 자료·실제 실행 결과와 대조해 채택, 부분 채택, 유지로 나눴습니다. 예를 들어 K116의 NAFLD 별칭 누락 지적은 채택해 별칭을 추가했습니다. K262 NTM의 MeSH 후보 누락 지적은 후보를 추가하되, MeSH와 CDC의 범위 차이 때문에 같은 개념으로는 승인하지 않았습니다(부분 채택). 지적 사항과 처리 결과, 수정 전후 실행 기록은 [AI 교차 검토 기록](https://github.com/minho00123/indication-atlas-submission/blob/main/docs/AI_REVIEW.md)에 있습니다. 두 AI의 의견 일치를 정답의 근거로 쓰지 않았으며, 이 교차 검토는 임상 전문가 검증이 아닙니다.

# 규칙 실행 대조의 설계와 재현

[리포트 열기](#materials/audit) · [전체 결과 다운로드](./downloads/rule-audit.json)

이 검증은 "저장한 300건 판정을 지금의 규칙과 사전으로 다시 처리하면 같은 결과가 나오는가(A)", "각 항목이 자기 자신의 기록 없이도 처리되는가(B)", "선언한 규칙이 지켜지는가(C)"를 확인합니다. 어떤 검토 지식을 재사용했고 어디서 사람 검토가 남는지 드러내는 것이 목적입니다. 원본 300행과 고정 판정을 바꾸지 않았습니다. 이 300행은 사전과 정책을 만들 때 사용한 개발 자료이며 독립 정확도 평가가 아닙니다.

## 별칭 조회와 대조 A

별칭 조회 무결성 검사는 등록된 419개 term→concept 연결이 색인에 보존되는지 확인합니다. 실행 중 파생한 짧은 이름은 이 419개 저장 연결의 분모에 추가하지 않습니다. 다의 별칭에 대해 후보가 보존됐는지 검사하며 단일 의미로 승인하는 검사가 아닙니다.

대조 A는 전체 검토 사전으로 300행의 키워드와 원문을 실행한 결과입니다. 기존 개념과 일치, 보류 행동 일치, 검토 필요, 규칙 미지원, 미등록, 다른 실행 결과를 구별합니다. 보류 행동이 같아도 세부 사유까지 같다는 뜻은 아닙니다. 모든 불일치를 색인 버그로 해석하지 않습니다.

## 대조 B: 행 출처 제거 후 재현성·의존성 대조

각 행을 실행할 때 다음을 제거합니다.

1. source_id가 그 행인 모든 종류의 별칭.
2. 그 행이 포함된 비교 쌍.
3. 그 행의 기존 레코드와 식 메타데이터.

다른 행의 검토 지식, 전체 개념 목록, CD·AML은 문서 정의 없이는 고르지 않는 안전 규칙 등 전역 정책은 남습니다. 같은 표현이 다른 출처에 등록되어 있으면 그 연결도 남습니다. 남은 type 1/2 diabetes mellitus 별칭에서 짧은 형태를 파생하는 전역 규칙도 유지됩니다. 파생 이름의 출처는 각 언급의 variant_sources에 기록합니다. 따라서 새로운 개념을 숨긴 홀드아웃이나 독립 정답 평가가 아닙니다.

제공 표현 별칭(PROVIDED_INPUT)은 297행에 있으며 K009·K018·K024에는 없습니다. 제거는 이 종류에만 한정하지 않고 5종의 모든 행 출처 별칭을 대상으로 합니다. 행별로 제거 수와 남은 같은 키워드 출처를 기록합니다.

B의 미등록은 제거 후 사용 가능한 색인에서 대상 표현을 찾지 못했다는 뜻입니다. 질환이 세상에 없다는 뜻이나 의미 판단 실패율로 사용하지 않습니다. 300행에서 만든 정책 자체는 남아 있으므로 이를 ‘새 데이터 일반화 성능’으로 설명하지 않습니다.

## 대조 C: 규칙·조건 감사

A와 B 각각에서 적용되는 규칙을 검사합니다. 원문 충돌의 자동 정정 방지, 다의 약어 보류, 입력·부분 구간 보호, 기존 조건 구간의 보존과 역할, OR 구조와 피연산자 해소, 비질환 유형, 기존 LOCAL 재사용 등을 구별합니다. 후보의 일반적인 정의 비교와 기본 의미의 모든 반대 문맥 해석은 사람 검토로 남습니다.

기대 구간·역할은 기존 고정 판정에서 가져왔습니다. 독립 주석자의 임상 정답이 아닙니다. 한 행에 여러 검사가 적용되므로 적용 행 수와 검사 횟수가 다릅니다. 미적용과 미지원, 사람 검토를 같은 통과 수로 세지 않습니다. G09·G11·G12의 데이터·근거·집계 무결성은 Python 빌드·검사에서 별도로 확인하며, 행별 의학 판단 통과 수를 만들어 넣지 않습니다.

## 재실행

Python 3.9 이상으로 기존 빌드·열람을 할 수 있습니다. JS 대조를 새로 실행하려면 Node.js 22 이상을 사용합니다. 추가 npm 패키지나 모델 호출은 필요하지 않습니다.

```bash
node --test tests/test_*.mjs
node tools/run_rule_audit.mjs --check
node tools/export_runtime_review.mjs --check
python3 tools/verify_rule_audit.py
python3 tools/build.py
```

규칙·색인 자료를 수정해 대조 결과를 새로 생성하려면 아래 명령을 사용하고 차이를 검토합니다.

```bash
node tools/run_rule_audit.mjs
python3 tools/build.py
```

`data/rule_audit_manifest.json`은 실행기·대조기·기준 입력·지원표·결과의 SHA-256을 연결합니다. Python 빌드는 저장된 결과의 입력 해시와 전체 집계를 검사해 오래된 결과를 그대로 배포하지 않습니다. GitHub 검사에서는 Node로 실제 재실행해 저장된 결과와 내용이 같은지 확인합니다. 파일 해시가 맞는다는 사실을 임상 정확도로 표현하지 않습니다.

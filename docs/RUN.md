# 실행과 제출 자료

- 웹: https://indication-atlas.netlify.app/
- 저장소: https://github.com/minho00123/indication-atlas-submission

!> **웹에서 확인:** 사전 검색, 키워드별 분류 결과, 판단 기준과 직접 입력해 보기 기능을 사용할 수 있습니다.
!> **로컬 실행:** Python 3.9 이상에서 `python3 tools/serve.py`를 실행하고 http://127.0.0.1:8787 을 엽니다. 추가 패키지나 API 키는 필요 없습니다.
!> **제공 파일:** 판단표 CSV, 별칭 CSV, 판정 JSON, 검증 결과와 실행 코드 ZIP을 내려받을 수 있습니다.

## 웹에서 확인하는 순서

1. **개요(첫 화면):** 결과 요약과 분류 결과 예시(나눈 사례: CD / 묶은 사례: NSCLC)의 연결 그림을 봅니다. 숫자 요약을 누르면 키워드·개념·별칭·보류 목록으로, 아래 안내를 누르면 판단 기준·사례·조사·보고서로 이동합니다.
2. **동의어 사전:** CD·NSCLC·eczema·NAFLD를 검색합니다. 개념의 연결된 이름을 누르면 그 이름이 들어온 항목의 근거로 이동합니다.
3. **분류 결과:** 300개 키워드를 검색하고 처리 상태로 거릅니다. 항목을 선택하면 제공 문맥과 판단 이유, 후보 정의와 출처가 나옵니다.
4. **판단 기준:** 공통 규칙 G01–G12를 읽고 사례별 검토에서 약어·범위·추가 조건·보류 사례를 비교합니다.
5. **직접 입력해 보기:** 개요의 안내나 사전 검색창 아래 링크로 엽니다. 키워드와 문맥을 입력하거나 여러 줄을 한 번에 처리할 수 있습니다. 미등록 표현은 MONDO·NCIt·MeSH 후보와 비교하고, 각 결과를 CSV·JSON으로 내려받을 수 있습니다.
6. **구축 보고서:** 구축 과정의 7단계, 유사 서비스 조사, 검증과 한계, 파일과 실행 방법을 확인합니다.

## 메뉴와 자료 위치

메인 메뉴는 개요 / 동의어 사전 / 분류 결과 / 판단 기준 / 구축 보고서입니다. 판단 기준에는 공통 규칙과 사례별 검토를, 구축 보고서에는 구축 과정 / 유사 서비스 조사 / 검증과 한계 / 파일과 실행 방법을 모았습니다. 기존에 공유한 가이드라인과 개념 비교 주소도 새 위치로 연결됩니다.

## 로컬 실행

Python 3.9 이상을 사용합니다. 추가 패키지 설치나 API 키가 필요 없습니다. 저장소 최상위 폴더에서 실행합니다.

```bash
python3 tools/serve.py
```

터미널에 표시되는 http://127.0.0.1:8787 주소를 엽니다. 종료는 Ctrl+C입니다. 다른 포트는 `python3 tools/serve.py --port 8790`으로 지정합니다.

## 빌드와 데이터 확인

```bash
python3 tools/build.py
python3 tools/dataset.py --term CD
python3 tools/score_legacy.py
python3 tools/verify_supplement.py
python3 -m unittest discover -s tests -p 'test_*.py'
```

정적 결과는 `dist/`에 생성됩니다. 파일을 더블클릭하는 대신 로컬 웹 서버 또는 배포 URL로 엽니다. 빌드는 고정한 판정을 검증·출력하며 새 의학 판정을 생성하지 않습니다. score_legacy.py는 구 정책 실험의 저장된 예측을 재채점하며 현재 사전의 정확도를 평가하지 않습니다.

## 분석 모듈 검사

웹의 [직접 입력해 보기](#analyze)는 외부 모델 없이 브라우저에서 실행합니다. 미등록 표현의 "MONDO·NCIt·MeSH에서 후보 비교하기"를 누를 때만 대상 표현을 EBI OLS와 NLM MeSH 공개 API로 보내며, 원문은 보내지 않습니다. 새 문서의 명시적 정의와 일부 조건 구간을 처리하며 기존 300행을 수정하지 않습니다. 규칙이 의도대로 작동하는지 확인하는 작성자 구성 개발·반례 입력 103건(`data/analyzer_cases.json`)은 화면에 두지 않고 아래 자동 테스트에서 확인합니다. 통과 수는 정확도가 아닙니다. Node는 선택 검사에만 필요합니다.

```bash
node --test tests/test_*.mjs
```

검사 사례와 통과 수는 독립 임상 정확도를 뜻하지 않습니다. [실행 원리·지원 범위·한계](#materials/methodology)를 함께 확인해 주세요.

[검증과 한계](#materials/audit)에서 다시 실행한 결과와 판단 규칙 검사, 상세 자료를 내려받을 수 있습니다. [검증 방법·재실행](#materials/audit?section=method)을 함께 제공합니다.

```bash
node tools/run_rule_audit.mjs --check
python3 tools/verify_rule_audit.py
```

## 배포

GitHub 저장소의 main 브랜치에 push하면 Netlify가 `python3 tools/build.py`로 빌드하고 `dist`를 배포합니다. 설정은 `netlify.toml`에 있습니다.

## 파일 안내

| 경로 | 내용 |
|---|---|
| app/ | 화면·스타일·브라우저 검색 코드 |
| data/ | 300행 판정, 개념·별칭·비교 사례·근거 목록·원본 XLSX |
| evidence/ | 공식 응답·MONDO 발췌·웹 인용 기록 |
| docs/ | 가이드라인·유사 서비스 조사·구축 방법·실행 설명 |
| tools/ | 데이터 검증과 정적 빌드·로컬 실행 |
| tests/ | 원문·검색·그룹·근거와 빌드 검증 |

웹의 CSV·JSON·ZIP은 같은 판정 스냅샷에서 생성합니다. ZIP에는 실행에 필요한 코드와 자료가 포함되고 Git 이력·가상환경·생성된 dist는 포함하지 않습니다.

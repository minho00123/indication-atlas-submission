# 새 문장 분석 시제품

[분석 화면 열기](#analyze)

기존 300건의 저장된 판단을 조회하는 화면과 별도로, 사용자가 입력한 새 표현·원문을 실행 중 분석합니다. 입력은 브라우저 메모리에서만 처리하며 서버나 외부 모델로 보내지 않습니다. 분석 결과는 JSON으로 내려받을 수 있습니다. 기존 판정·별칭 사전을 자동 수정하지 않습니다.

## 실제로 구현한 것

1. 검토한 이름·별칭을 단어 경계와 긴 표현 우선으로 찾습니다. AML이 FAMILY 같은 단어 안에서 일치하지 않도록 합니다.
2. 문서에 있는 긴 이름(약어) 정의를 찾고 긴 이름을 기존 개념과 대조합니다. 등록되지 않은 새 약어도 긴 이름을 확인하면 해당 문서 안에서 연결할 수 있습니다.
3. 여러 개념을 뜻하는 CD·AML은 명시적 정의가 없으면 보류합니다. 다른 질환의 단순 동시 언급은 약어 해소 근거로 사용하지 않습니다.
4. 같은 약어의 정의가 충돌하거나 긴 이름을 확인하지 못하면 보류합니다. 문서에서 확인한 새 별칭을 다른 입력으로 전파하지 않습니다.
5. 키워드와 원문의 확인 가능한 개념이 다르면 입력 충돌 또는 등록된 범위 차이로 표시합니다. 어느 필드를 정정할지 자동 결정하지 않습니다.
6. 일부 상태·치료·기간 표현을 원문 구간으로 추출합니다. 이름에 포함된 acute·chronic·HER2 등은 이름 구성 요소로 구별합니다.
7. 직접적인 부정·추정 표현을 언급 개념과 별도 필드로 기록합니다. 질환명이 등장했다고 환자 진단을 확정하지 않습니다.

## 입력을 바꾸면 달라지는 결과

| 대상 표현 | 새 원문 | 시제품의 처리 |
|---|---|---|
| CD | Patients with CD. | 다의 약어로 보류 |
| CD | Crohn disease (CD) is the target. | 문서 정의를 근거로 크론병 개념 연결 |
| CD | Celiac disease (CD) is the target. | 문서 정의를 근거로 셀리악병 개념 연결 |
| T2D | Type 2 diabetes (T2D) is mentioned. | 긴 이름을 확인해 이 문서의 새 약어 연결 |
| Acute myeloid leukemia | Relapsed acute myeloid leukemia after prior therapy. | 기본 개념과 이름 구성 요소 acute를 유지하고 재발·이전 치료를 별도 추출 |
| eczema | Adults with plaque psoriasis. | 서로 다른 개념이므로 입력 충돌로 보류 |
| NSCLC | No NSCLC is reported. | 언급 개념은 연결하면서 직접 부정 표지를 별도로 기록 |

기존 K007·K008의 증상 단서만 보고 의미를 추론하는 일반적인 문맥 이해 모델은 아닙니다. 이 시제품은 문서 내 명시적 정의와 등록된 표현을 사용합니다. 표면상 비슷한 임의의 긴 이름을 외부 표준으로 새로 승인하지 않습니다.

## 출력의 의미

- **개념 연결:** 등록된 표현 또는 확인한 문서 정의로 기존 개념에 연결했습니다. 임상 진단의 확정이나 의학적 정확도 승인을 뜻하지 않습니다.
- **기존 자체 개념 연결:** 이미 검토한 LOCAL 개념에 연결했습니다. 새 LOCAL을 자동 생성하지 않습니다.
- **보류·검토 필요:** 다의성, 정의 충돌, 입력 필드 충돌, 범위 차이, 미등록 표현 등을 구별해 표시합니다.
- **질환명 구성 요소:** 인식한 이름 구간 안의 수식어입니다. 독립 환자 관찰로 복사하지 않습니다.
- **원문별 추가 조건:** 지원 패턴에서 찾은 문서 구간입니다. 여러 질환이 있으면 어느 질환의 조건인지 자동 배정하지 않습니다.
- **언급 표지:** 제한된 직접 부정·추정 패턴입니다. 모든 부정 범위나 임상적 확실성을 해석하는 모델은 아닙니다.

원문 구간의 인덱스는 브라우저 문자열과 일치하는 UTF-16 코드 단위입니다. 출력의 start/end로 원문을 잘랐을 때 해당 text와 일치하는지 검사합니다.

## 현재 지원 범위

기존 287개 개념과 검토한 별칭을 사용합니다. 새로운 질환의 정의나 외부 코드를 실시간으로 수집하지 않습니다. 부분 일치만으로 새 개념을 승인하지 않습니다. 명시적 정의가 없는 복잡한 약어 해소, 일반적인 의학적 추론, 전체 환자 적격성 비교는 구현 범위 밖입니다.

추출 패턴은 Metastatic·Relapsed·Refractory·prior therapy, 일부 기간 표현과 인식한 이름 안의 acute·chronic·HER2 정보에 한정됩니다. 지원 패턴에서 찾지 못했다는 결과는 조건이 없다는 뜻이 아닙니다. 복잡한 부정·가족력·과거력·시간 관계 및 여러 질환 간 조건 배정은 별도 검토가 필요합니다.

## 새 입력 검사와 한계

작성자가 구성한 개발·반례 입력은 `data/analyzer_cases.json`에 있습니다. 입력을 바꿨을 때 의도한 규칙이 유지되는지, 정의가 없거나 충돌할 때 보류하는지, 조건이 새 원문에서 추출되고 기존 행의 조건은 복사되지 않는지 확인합니다.

분석 화면의 ‘개발·반례 검사’에서 같은 모듈을 실행해 결과를 확인할 수 있습니다. 이는 독립 주석자의 정답셋, 미사용 임상 데이터의 정확도 또는 일반화 성능 평가가 아닙니다. 이 검사를 보면서 구현을 수정하므로 개발 검사로 표시합니다.

Node.js 22 환경에서는 다음 명령으로 같은 검사를 실행할 수 있습니다. Node는 이 선택적 검사를 위한 환경이며 정적 빌드와 로컬 웹 실행에는 추가로 필요하지 않습니다.

```bash
node --test tests/test_analyzer.mjs
```

다음 단계는 지원 범위를 먼저 고정하고, 별도 주석과 신규 자료로 약어 해소·조건 추출을 각각 평가하는 것입니다. 현재의 구조화된 구간 추출과 문서 내 정의 해소를 완성된 임상 판정기로 표현하지 않습니다.
